# เฉลยบั๊ก BUG_MODE=1

> ไฟล์นี้เป็นเฉลยสำหรับผู้สอน/QA เท่านั้น — เปิดบั๊กด้วย env `BUG_MODE=1` ของ container `mongkol-web` (`$env:BUG_MODE='1'; docker compose up -d` ในโฟลเดอร์ `web/`)
> ทุกบั๊กควบคุมจาก `src/shared/runtime-profile.ts` (`runtimeProfile()`) จุดเดียว

| # | หมวด | กฎที่ละเมิด | อาการเมื่อ BUG_MODE=1 | ค่าที่ถูก (BUG_MODE=0) | จับได้ด้วย |
| --- | --- | --- | --- | --- | --- |
| 1 | การคำนวณตัวเลข | BR-LP-06 (ผลรวมรวมค่าอักษร) | `letterTermMode = 'set'` — อักษรซ้ำในหมวดถูกนับครั้งเดียว สูตรบนหน้าจอแสดงเพียงอักษรเดียวจึงดูสอดคล้องกับผลรวม | `ฆฆ 9999` = 42 · `กก 9900` = 20 · `9ฆฆ 9999` = 51 · `9ฎฎ 9999` = 63 | LD-S03, LD-S07, LD-S10, LD-S11 (ผลจากบั๊ก: 39 / 19 / 48 / 54 และ Grade เปลี่ยน) |
| 2 | การตรวจสอบ input | BR-LP-02 / §4.2 (เลขนำหน้าต้องเป็น 1–9) | `minPrefix = 0` — `0กข 1` ผ่านและแสดงผลรวมปกติ (นำหน้า 0 ไม่เปลี่ยนผลรวม จึงดูสมเหตุสมผล) | `0กข 1` → 400 `PLATE_INVALID_PREFIX` | LD-I01 |
| 3 | สถานะ/ตัวนับหลังทำรายการ | NFR-06 / §4.4 (ล็อกเมื่อผิดครบ 5 ครั้ง) | `lockAfterFailures = 6` — `locked.test` (มี `failed_login_count=4`) ผิดครั้งที่ 5 ได้ 401 `AUTH_INVALID` และยัง login ได้ทันที | ครั้งที่ 5 → 423 `AUTH_LOCKED` · รหัสถูกทันทีหลังนั้น → 423 | LG-04, LG-05 |
