# Reference & Mock Data

โปรเจกต์ยังไม่มีฐานข้อมูลจริง ไฟล์ในโฟลเดอร์นี้จึงใช้เป็น **Seed / Fixture** สำหรับพัฒนาและทดสอบ Rule Engine, UI และ Regression Tests

| ไฟล์ | เนื้อหา | ที่มา | สถานะ |
| --- | --- | --- | --- |
| `plate-rules.json` | สูตรผลรวม, ค่าอักษร (ทักษา), ระดับผลรวม, เลขตามวันเกิด, คู่เลข/รูปแบบควรเลี่ยง, เลขตามอาชีพ | Wongnai (สรุปสาระ) | Draft — รอตรวจทาน |
| `plate-rules-allianz.json` | เลขดี/เลี่ยง + อักษรเลี่ยงตามวันเกิด, ความหมายผลรวมหลักเดียว, เลขต้องห้ามทั่วไป | Allianz (สรุปสาระ) | Draft — รอตรวจทาน |
| `source-comparison.md` | ตารางเทียบ Wongnai / Allianz / DECODER159 และจุดที่ขัดแย้ง | สรุปเอง | อ่านก่อนเลือก Default Rule Set |
| `pair-meanings.json` | ข้อดี/ข้อเสียคู่เลข 25 กลุ่ม | ความเชื่อทั่วไป (สรุปเอง) | Mock — รอ Domain Expert |
| `phone-categories.json` | นิยามเบอร์มังกร/หงส์/เศรษฐี/VIP/สวย, อาชีพ, เป้าหมาย | สมมติ | Mock |
| `mock-listings.json` | ประกาศเบอร์และทะเบียนตัวอย่าง | สมมติ | Mock |
| `mock-reviews.json` | รีวิวตัวอย่าง รวมเคสทดสอบ Moderation | สมมติ | Mock |

## กติกาการใช้

1. ทุกไฟล์มี `ruleSetId`, `version`, `status`, `source` และ Rule Engine ต้องแสดงค่าเหล่านี้ในผลลัพธ์ (US-PH-001, US-AD-002)
2. ข้อมูลที่ `status` เป็น `mock` ห้ามขึ้น Production และหน้าเว็บต้องแสดงป้าย "ข้อมูลตัวอย่าง"
3. คู่เลขหรือกฎที่ไม่อยู่ในไฟล์ให้แสดง `ไม่มีข้อมูล` ห้ามสร้างคำทำนายเอง
4. ข้อมูลจากเว็บภายนอกเก็บเป็นสรุปสาระเท่านั้น ไม่คัดลอกข้อความต้นฉบับ และต้องตรวจสิทธิการใช้ก่อน Production
5. เบอร์และทะเบียนใน Mock เป็นตัวอย่าง อาจบังเอิญตรงกับเบอร์จริง จึงห้ามใช้ทดสอบการโทรหรือส่ง SMS
6. เมื่อมีฐานข้อมูลจริง ให้ใช้ไฟล์เหล่านี้เป็น Seed Migration และ Regression Test Cases
