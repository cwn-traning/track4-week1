# สรุป Session — ล่าบั๊กโหมด BUG_MODE=1 ด้วยชุด E2E และรายงาน `BUG-HUNT.md`

> **วันที่:** 2026-11-07 · **อินพุต:** ชุดทดสอบ [`e2e/`](../e2e/) จาก [session 07](07-playwright-e2e-suite-session-summary.md), [`TEST-PLAN.md`](../TEST-PLAN.md) (หัวข้อ 5 และ 8), ผลโหมดปกติ (`e2e/index.html`, `triage.json`, `test-report`)
> **ผลลัพธ์:** [`BUG-HUNT.md`](../BUG-HUNT.md) ส่วนที่ 1 · [`e2e/triage.json`](../e2e/triage.json) (เพิ่มฟิลด์ `bugMode`) · [`e2e/index.html`](../e2e/index.html) (สร้างใหม่) · สำรองผลโหมดปกติที่ [`e2e/normal-mode/`](../e2e/normal-mode/)
> **ข้อจำกัดที่ทำตาม:** ไม่เปิด `web/BUGS.md` · ไม่อ่านโค้ดใน `web/` เพื่อหาบั๊ก · ไม่แก้ test หรือแผนให้ผ่าน · ยังไม่ได้ commit

## 1. คำขอ

0. เปิดเว็บด้วย `$env:BUG_MODE=1; docker compose up -d` → รอ healthy → เช็ก `data-bug-mode="1"`
1. ก่อนรัน สำรอง `e2e/index.html`, `e2e/triage.json`, `e2e/test-report` ไปที่ `e2e/normal-mode/`
2. รัน `npx playwright test` แล้ว `npm run test:gif`
3. ดูข้อที่ล้ม (ภาพ/GIF) แยก "ล้มใหม่ในโหมดบั๊ก" กับ "ล้มเหมือนโหมดปกติ" และจำแนกว่าเว็บผิด หรือ test/แผนผิด → บันทึก `triage.json` → สร้าง `index.html` ใหม่
4. เขียน `BUG-HUNT.md` ส่วนที่ 1 (ตาราง BUG | TC | ระดับ | ขั้นตอนทำซ้ำ | ผลที่คาดหวัง (ที่มา) | ผลจริง | GIF | MP4) และเทียบกับหัวข้อ 8 ของแผน

## 5. เทียบกับ TEST-PLAN.md §8.1
